# EP01 17컷 메신저 확대 UI — 구현 준비와 적용 절차

- 작성: 2026-11-21 · 상태: **준비 문서. 코드 미구현, 원화 미연결.** 선행 문서: `docs/EP01_CUT17_MESSENGER.md`
- 이 문서는 구현 전에 정해 둔 것과 순서만 적는다. 임의 좌표·임의 이미지로 최종 구현하지 않는다.

## 1. 결정 사항 (사용자 확정)
1. 승인 원화 `ep01v3-017-messenger-approved-DRAFT.webp`를 **그대로 유지**한다(빈 화면 변형은 만들지 않는다).
2. 원화 속 모니터의 메신저 글자는 **불투명한 웹 UI로 덮는다**(화면 윤곽에 원근 합성, `.scr`). 원화 글자가 비쳐 보이면 안 된다.
3. 공지 내용은 **확대 인셋**(`.scr-zoom`)에 표시한다. 기존 휴대폰 UI의 확대 인셋 구조를 재사용한다.
4. 320~768px에서 인셋 본문 **13px 이상**, 본문이 `messenger.body`와 **정확히 일치**함을 검증한다.
5. 모니터 좌표(quad·clip)는 **실제 이미지를 보고 잰 값만** 쓴다.
6. 병합: **`ep01-phone-ui-refactor`만 먼저**. `ep01-cut17-messenger`는 원화 연결과 확대 UI가 끝날 때까지 보류.

## 2. 왜 휴대폰 브랜치가 먼저인가
확대 인셋·합성 레이어(`js/screenui.js`의 `ZOOM`·`buildZoom`·`fit`, `css/phone-system.css`, `tools/qa/v3.js`의 `zoom.*` 검사)는 `ep01-phone-ui-refactor`에만 있다. 17컷 브랜치는 이 코드 없이는 구현·검수할 수 없다. 사전검증에서 두 브랜치는 충돌 없이 병합되었다(겹침: `data/ep01v3-bubbles.js` 한 파일, 자동 병합).

## 3. 구현 준비 — 바뀔 곳 (원화 도착 후 구현)

| 파일 | 내용 |
|---|---|
| `data/ep01v3-screens.js` | `"17"` 항목 추가: `quad`(모니터 화면 네 모서리), `clip`(화면 윤곽), `aspect`, `view: "messenger"`, `theme`, `fs`, `zoom: {x, y, w, fs, parts: "messenger", frame: false}`, `artText`(원화 속 글자 영역 bbox) — **값은 §4 측정 후** |
| `js/screenui.js` | `VIEWS.messenger`(모니터용 데스크톱형 메신저 창)와 `ZOOM.messenger` 추가. 문구는 데이터의 `messenger`(발신자·날짜·시각·본문)만 읽는다. 문구를 새로 만들거나 복사하지 않는다 |
| `css/phone-system.css` | `.su-v-messenger` 스타일(23컷 데스크톱 UI와 같은 계열) |
| `js/app.js` | 17컷 렌더 시 `messenger`를 화면 spec에 넘기는 연결 한 줄(필요하면) |
| `tools/qa/v3.js` | §5 검사 추가, 합성 화면 개수 기대값 20 → 21(경고 기준 갱신, 낮춤 아님) |
| `data/ep01v3.js` / `tools/connect_cut17_messenger.py` | 원화 연결(기존 스크립트) |

바꾸지 않는 것: 말풍선(17컷은 계속 없음), 18컷 이후, 70컷판, 다른 컷 대사.

## 4. 원화 도착 후 모니터 좌표 측정 절차
원화에는 글자가 있어 화면 영역을 자동 분리할 수 없다 → **눈으로 읽은 값을 기록하고, 겹쳐서 확인**한다.
1. 원화를 원본 크기 그대로 열어 모니터 화면 **안쪽 테두리(베젤 안)** 네 모서리 픽셀 좌표를 잰다. 가려지는 모서리가 있으면 보이는 변을 연장한다(86·104·94:1컷 선례).
2. 비율(0~1)로 변환해 `quad`·`clip`에 기록하고, **원화 속 글자의 bbox**를 `artText`로 함께 기록한다.
3. 디버그 합성 스크린샷(덮개 반투명 on/off)으로 덮개가 베젤을 침범하지 않고 `artText`를 **여유 1~2% 두고 완전히 덮는지** 확인한다. 조금이라도 비치면 `clip`을 넓히지 말고 quad를 다시 잰다.
4. **16컷 연속성**: 16컷 모니터 화면은 1080×1350에서 x 324~850, y 141~436(가로:세로 ≈ 1.78:1, `23:0`의 `photo`값). 17컷 모니터가 같은 물건인지(화면 비율, 베젤 색·두께, 스탠드, 책상 위 위치 관계, 옆 노트북) 나란히 비교한다. 화면 비율이 16:9에서 어긋나면 `aspect`를 실측한다.
5. 인셋 위치(`zoom.x·y·w`)는 모니터 쪽에서 선이 이어지고 **승민 뒷모습·모니터 화면·핵심 소품을 가리지 않는** 빈 곳에 둔다. 위치는 원화를 본 뒤 정한다.

## 5. QA 검사 항목 (17컷 추가분)
| 검사 | 기준 |
|---|---|
| `msg17.cover` | `.scr` 불투명(opacity 1, 필터·블렌드 없음), 합성 화면이 `artText` bbox를 모두 덮음 |
| `msg17.zoom` | `.scr-zoom` 존재·`is-fit`, `aria-hidden="true"`, 컬럼·컷 위아래 안, 실제 모니터 화면 위에 겹치지 않음 |
| `msg17.font` | 인셋 본문 **절대 크기 13px 이상**(320·360·390·430·768 모두). 기존 `zoom.font`는 폭 배율 `u`로 환산해 320px에서 약 11px까지 허용하므로 17컷에는 별도로 절대값 검사 |
| `msg17.text` | 인셋·합성 화면 본문 = `messenger.body` 문자열과 정확히 일치(공백·문장부호 포함). 발신자 "최기훈 교사", 날짜 "10월 30일(금)", 시각 "16:40"도 일치 |
| `msg17.noorig` | 17컷에 `.bv4-b`(말풍선)·`.bv4-screen` 없음(중복 출력 금지) |
| 기존 | 104컷 QA FAIL 0, 70컷 QA 실패 0 / 확인 11, `screen.fit`·`screen.dup` 통과 |
13px 확보 방법: `zoom.fs`는 360px 기준값이라 320px에서 `fs × 320/360`이 된다. 13px 이상이 되려면 `fs ≥ 14.7` → **15 사용**(63컷 인셋과 같은 값). 본문 43자는 약 170px 폭에서 13px 기준 4줄 안팎(측정 근사)이다.

## 6. 적용 순서 (승인 지점 표시)
1. **[승인]** `ep01-phone-ui-refactor`를 `ep01-redesign-v3`에 병합 → 104컷·70컷 QA 재실행.
2. **[승인]** 갱신된 기준 브랜치를 `ep01-cut17-messenger`에 가져온다(병합 또는 리베이스, 방식은 승인 때 정한다). 충돌 없음 확인됨.
3. 승인 원화 파일 도착 → 새 파일명으로 `assets/cuts/ep01v3/`에 추가(기존 원화 수정 없음).
4. `connect_cut17_messenger.py` 실행(image·imageSize·imageLqip, QA 허용 목록). 비율이 4:3이 아니면 중단 후 사용자 확인.
5. §4 모니터 좌표 측정 → 화면 항목·렌더러·CSS 구현 → §5 QA 추가.
6. 320·360·390·430·768px에서 16→17→18컷을 눈으로 검수, 기준 원화(35·50·66)와 비교, 스크린샷을 `docs/qa/ep01v3/screenshots/`에 WebP로 저장.
7. 104컷 QA·70컷 QA 통과 확인 → 사용자에게 결과 보고. **[승인]** 사용자 확인 뒤 기준 브랜치 병합(배포는 별도 승인).

## 7. 현재 한계·열린 질문
- 원화·모니터 좌표가 없어 좌표 의존 항목은 전부 미구현. 이 문서의 숫자(16컷 좌표, 13px·4줄 근사)는 기존 데이터와 측정 근사값이다.
- 원화 속 글자와 `messenger.body`가 다르면(예: 오탈자) 웹 UI가 덮더라도 정본은 `messenger.body`다. 원화 글자 차이는 보고하되 원화는 고치지 않는다.
- 모니터 UI는 휴대폰이 아니므로 iPhone 17 규칙 대상이 아니며, 데스크톱형(23컷 계열)을 따른다. 메시지 모자이크·흐림 금지, 메시지 원문 창작 금지는 그대로 적용된다.
