## 3. iOS Safari·Android Chrome 호환성 (코드 검사)

| 기능 | iOS Safari | Android Chrome | 미지원 시 |
|---|---|---|---|
| `:has()` (분위기 경계 그라데이션) | 15.4+ | 105+ | 경계가 한 번에 바뀜 (대체 동작) |
| `aspect-ratio` (그림 영역 높이) | 15.0+ | 88+ | **그림 영역 높이 0 — 그림 안 보임** |
| `svh` | 15.4+ | 108+ | 100vh 로 대체 |
| `loading="lazy"` | 15.4+ | 77+ | 그림 9.8MB 를 처음에 다 받음 |
| `inset` | 14.1+ | 87+ | 그림 위치 어긋남 |
| flex `gap` (말풍선 간격) | 14.1+ | 84+ | 말풍선이 붙음 |
| WebP | 14.0+ | 32+ | 그림 전부 깨짐 |
| `backdrop-filter` | `-webkit-` 있음 | 76+ | 상단 바 흐림 없음 |

정리: **iOS 15.4 이상 = 의도대로**, iOS 15.0~15.3 = 경계 급전환·지연 로딩 없음, iOS 14 이하 = 그림 안 보임. Android Chrome 108 이상 = 의도대로.
iOS 에서는 Chrome·카카오톡·네이버 앱 안 브라우저도 모두 Safari 와 같은 WebKit 이라 위 iOS 버전이 그대로 적용된다. **이 판정은 실제 iOS 실행이 아니라 코드 검사 결과다.**

## 4. 70컷 점검 (말풍선·이미지 경계·가로 넘침·지연 로딩)

- 가로 넘침: 320·360·375·390·412·430·768px 모두 0.
- 지연 로딩: 그림 155개 모두 `loading="lazy"`. 첫 화면에서 받는 그림 2~5개. 3G 에서는 1번 화면에 들어오기 전에 못 받는 컷이 많음 (2절 2번).

## 5. 44컷 벽시계 테두리 분석

`assets/props/auditorium-clock-frame.webp` (1254×1254) 위에 `assets/overlays/auditorium-clock-1030.svg` 가 같은 위치·같은 폭(가로 62%)으로 겹친다.

- SVG 는 불투명한 문자판 원(중심 497,506 / 반지름 416, viewBox 1000)을 그린다 → 테두리 그림 기준 **반지름 522px 안쪽은 SVG 가 완전히 덮는다.**
- 테두리 그림의 반투명 구멍(안쪽 반투명 픽셀 215,611개 + 옅은 픽셀 207,981개)은 **모두 반지름 522px 안쪽**에 있다.
- 떨어진 점 **36개(41px)는 모두 반지름 342~406px** → 전부 문자판 아래.
- 문자판 밖 테두리(반지름 522~610px)의 반투명 픽셀은 바깥·안쪽 경계의 정상적인 부드러운 가장자리뿐. 테두리 바깥에 옅은 픽셀 6,499개가 있으나 불투명도가 낮아 화면에서 안 보임.

## 8. 총괄 판단 반영 (2026-11-12)

판단: "11·51·65컷은 실제 휴대폰처럼 알림 미리보기의 말줄임을 유지. 12컷은 메일을 열지 않은 상태의 확대 알림이므로 320px 에서도 마지막 문장까지 전부 보이도록 해당 컷 레이아웃만 수정."

- `css/style.css`: `.phone.is-focus .notif-body` 의 6줄 제한을 없앰 (`display: block`). 확대 알림(`focus: true`)은 1화에서 **12컷만** 쓰므로 다른 컷은 바뀌지 않는다. 휴대폰 화면 높이는 내용에 맞춰 늘어나는 구조라 휴대폰 틀에서 잘리지 않음.
- 360px 이상에서는 원래도 6줄 안에 들어가 화면이 같다 (12컷 375px 캡처 수정 전후 비교).
