## 2. 연출

- 말풍선 꼬리는 **발화자**를 향한다. 화면 밖 발화와 전화 음성은 정해진 형식을 따른다.
- 인물의 얼굴(눈·입)과 중요한 행동(손, 휴대폰, 핵심 소품)을 말풍선으로 가리지 않는다. 경계-상, 경계-하, 컷 사이, 틀 밖 자리를 적극 쓰되, 글자는 말풍선 안에 완전히 들어가야 한다.
- 글자 크기는 말 16px, 독백 15px, 자막 13.5px 이상이다. 어떤 폭에서도 13px 미만 글자를 두지 않는다.
- 기존 콘티의 **대사·시각·날짜·컷 순서·스토리·반전 구조**를 보존한다. 사용자가 요청해 승인한 변경만 예외이며, 무엇이 바뀌었는지 보고한다.
- 1화 고정 사항: 해인의 09:50 업무메일 본문은 공개하지 않는다. 10/31 오전 강당에 해인은 등장하지 않는다. 문상윤은 목소리만 나온다. 마지막 컷에서 범인과 반전을 노출하지 않는다. 17번 보관함, 파란 파일 17, C-17 출입카드는 서로 다른 물체다.
- 표정: 웃음은 정해진 컷(11~12, 18~19, 47)만 허용하고, 85컷은 아주 작은 안도로 그린다. 효은에게 수상한 연출 장치(안경 반사로 눈 가리기 등)를 넣지 않는다.
- 콘티에 있는 **글자형 효과음**은 유지하거나 복원할 수 있다. 콘티에 없는 효과음은 새로 만들지 않는다.
- **실제 오디오 재생 기능은 추가하지 않는다.**

## 3. 휴대폰

- 외관은 **iPhone 17 일반형**이다. 승민은 **Black**, 해인은 **Lavender**이며, 두 사람의 폰은 다른 물건으로 구분되어야 한다.
- 휴대폰 화면은 **공통 디자인 시스템**을 쓴다(현재 `ep01-phone-ui-refactor` 브랜치의 `css/phone-system.css`와 `js/screenui.js`의 `status()`). 승민은 어두운 화면, 해인은 밝은 화면이다. 상태 표시줄에는 Dynamic Island를 두고, 메시지 화면은 iOS 메시지형으로 만든다. 컷마다 다른 것은 데이터(시각, 내용, 좌표)뿐이다.
- 메시지에 **인위적인 모자이크나 흐림을 넣지 않는다.** 강조는 하이라이트로 한다. 원화 속 손가락이 화면을 가리는 것은 허용한다.
- 메시지 원문은 **창작하지 않는다.** 대본에 없는 문장, 시각, 발신자를 만들지 않는다. 대본의 `○` 표기(예: `031-7○○-○○○○`)는 그대로 둔다. 대본에 화면 내용이 없으면 화면을 비워 둔다.
- 휴대폰 UI를 만들 때는 SVG·CSS를 쓸 수 있다. 이것은 화면 UI에만 해당하며, 기기 외관 그림은 원화로 그린다.
- 원화가 바뀌면 그 컷의 화면 좌표(`quad`·`clip`·`aspect`)를 다시 잰다.

## 4. 개발 및 검수

### 4-1. 범위와 브랜치

- 수정 대상은 **EP01 104컷판**(`#ep01v3`, `data/ep01v3*.js`)이다.
- **기존 70컷판**(`#ep01`, `data/ep01.js`, `assets/cuts/ep01/`)은 원본 그대로 보존한다.
- `main`·`gh-pages`는 사용자 승인 없이 변경하지 않으며, 배포(공개 URL 생성 포함)도 하지 않는다.
- **EP02**는 별도 요청이 있을 때까지 작업하지 않는다.
- 병렬 작업은 `ep01-redesign-v3`에서 갈라진 **독립 브랜치**에서 한다. 다른 작업 브랜치와는 사용자 승인 없이 병합하지 않는다.
- 외부 이미지 생성 서비스나 공개 범위가 있는 서비스는 사용자 승인 후에만 쓴다.

### 4-2. 검수 (두 가지를 따로 실시)

**① 자동 QA** — 저장소 루트에서 `python3 -m http.server 8765`를 실행한 뒤 다음을 본다.
- 104컷판: `http://localhost:8765/tools/qa/v3.html?auto` → FAIL 0
- 70컷판 회귀: `http://localhost:8765/tools/qa/qa.html?ep=ep01` → 기준선 FAIL 0 / WARN 11에서 나빠지지 않아야 한다
- Windows: `powershell -ExecutionPolicy Bypass -File tools\qa\run.ps1`(70컷판)
- 검사 기준값을 낮춰 통과시키지 않는다.

**② 시각적 디자인 검수** — 실제 브라우저(Chromium 등)에서 **320·360·390·430·768px** 폭으로 처음부터 끝까지 읽으며 확인한다.
- 글자 잘림, 비율 왜곡, 그림 가림, UI 겹침, 가로 스크롤
- 얼굴·의상이 승인 설정과 맞는지, 기준 원화와 화풍이 맞는지
- 말풍선 꼬리 방향, 얼굴·행동 가림
- 스크린샷은 `docs/qa/ep01v3/screenshots/<작업명-날짜>/`에 WebP로 남긴다.
