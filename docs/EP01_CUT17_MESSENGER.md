## 2. 정본 대사 처리 방식

1. **17컷의 정본 공지 문구는 위 메신저 문장**이다. 사용자가 승인한 원화(`ep01v3-017-messenger-approved-DRAFT.webp`) 모니터 화면 안에 들어 있다. 따라서 웹 말풍선으로 다시 쓰지 않는다.
2. `data/ep01v3.js` 17컷은 `lines: []`(렌더러는 말풍선을 만들지 않음). 이전 두 줄(최기훈 공지·교사 응답)은 삭제하지 않고 `legacyLines`에 **폐기된 직접 공지안 기록**으로 남기며 렌더링하지 않는다(렌더러가 읽지 않는 필드).
3. 새 문구와 발신자·날짜·시각은 같은 컷의 `messenger` 필드에 **기록용**으로 둔다(`layer: "in-art"`). 이 값은 화면에 출력되지 않으며, 원화의 글자와 어긋나는지 비교하는 기준이다.
4. `data/ep01v3-bubbles.js` 17컷은 `lines: []`, `zones: []`로 비웠다. 옛 화이트보드·최기훈 보호 영역은 옛 원화 기준이라 폐기했다.
5. `tools/qa/ep01v3.spec.json`의 17컷 기준(`lines`, `at`)을 빈 배열로 갱신했다. 사용자 승인 변경에 맞춘 갱신이며, 검사 기준값을 낮춘 것이 아니다. 다른 컷의 기준은 그대로다.
6. 다른 컷의 대사는 변경하지 않았다. 18컷 이후 효은·승민 대화(18컷 "승민쌤도 내일 나오세요?"…)는 그대로 이어진다.

### 확인이 필요한 점 (사용자 결정)
- **그림 속 글자 규칙**: `docs/EP01_PRODUCTION_RULES.md` §1은 그림 속 한글·숫자를 원화에 생성하지 않고 웹 레이어로 얹도록 한다. 이번 승인 원화는 공지 문구가 이미지 안에 있다고 전달받았다. 사용자의 최신 지시가 우선이므로 이미지 안 글자를 그대로 쓰는 것으로 기록했다. 이미지가 도착해 글자가 실제로 들어 있는지·문구가 위 정본과 같은지 확인하고, 다르면 웹 레이어(휴대폰/화면 UI 방식)로 얹을지 사용자에게 묻는다.
- 문구가 이전 안과 다르다("아홉 시, 강당입니다" → "오전 9시, 강당에서 진행합니다", "다들" → "모두"). 사용자 제공 문구를 그대로 썼다.

## 3. 승인 원화 연결 준비 상태

- 승인 원화는 **아직 저장소에 없다.** 임의 이미지로 대체하지 않았다. 현재 17컷은 기존 `ep01v3-017-final-DRAFT.webp`(옛 최기훈 직접 공지 그림)를 **임시로 그대로 표시**한다(말풍선 없음). 이 그림은 새 연출과 맞지 않으므로 최종본이 아니다.
- 원화가 들어오면 다음만 하면 된다.
  1. 파일을 `assets/cuts/ep01v3/ep01v3-017-messenger-approved-DRAFT.webp`로 추가한다(새 파일. 기존 원화는 수정·삭제하지 않음).
  2. `python3 tools/connect_cut17_messenger.py --dry-run` 확인 후 `python3 tools/connect_cut17_messenger.py` 실행. 17컷의 `image`·`imageSize`·`imageLqip` 세 필드와 `tools/qa/v3.js` 승인 이미지 허용 목록에 `017-messenger-approved` 한 항목만 바꾼다. 비율이 4:3이 아니면 중단하고 사용자 확인을 요청한다.
  3. 104컷 QA·70컷 회귀 QA·320~768px 시각 검수, 기준 원화(35·50·66)와 나란히 비교, 사용자 승인.
- 원화가 바뀌면 화면 좌표는 이 컷에는 없다(메신저 글자는 원화 안). 말풍선은 만들지 않으므로 `zones`도 필요 없다.
