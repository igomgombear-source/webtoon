# 코어 개선 제안 — 작은 항목 (필수 아님)

요청: Claude Code(말풍선·대사 모듈) → 통합 담당 · 2026-11-24 · **처리: 2단계 통합** — 1) `Studio.store.batch` 구현 2) 컷 머리글·QA 에 모듈 이름 3) `cut` 이벤트 `changed` 4) `Frame.sync()` 는 원래부터 언제나 Promise 를 돌려준다(해석값만 다름 — 문서화로 정리)

1. **원자적 일괄 편집 API** `Studio.store.batch(label, fn)` — `fn(set)` 안의 여러 `set` 을 변경 이벤트 한 번·실행 취소 한 단계로 묶는다. 지금은 `store.set` 한 번마다 `change` 가 나가 렌더러가 매번 다시 그리려 한다. 대사·말풍선 모듈은 편집 한 동작을 한 번의 `set` 으로 설계해 우회했지만(조각 상태를 부모 편집 항목 안에 둠), 다른 모듈에서 여러 요소를 한 번에 바꿔야 하면 필요하다.
2. **컷 머리글의 편집 모듈 이름** — `shell.js` `cutHead()` 가 편집 모듈을 ID(`dialogue`, `bubbles`)로 표시한다. `S.modules[id].label`(대사·말풍선)을 쓰면 읽기 쉽다.
3. **`cut` 이벤트 중복** — `Studio.stage.select(no)` 는 같은 컷을 다시 골라도(폭·모드 전환) `cut` 이벤트를 낸다. 모듈은 `onCut(no)` 에서 이전 컷과 비교해 선택을 유지하도록 처리했다(말풍선·대사 모듈). 이벤트에 `changed:true|false` 를 넣어 주면 단순해진다.
4. **`Frame.sync()` 반환값** — 회차 그리기 중이면 `queue`, 컷 단위면 바뀐 컷 배열을 돌려줘 호출자가 일관되게 `await` 하기 어렵다. 항상 `Promise` 로 통일하면 모듈·테스트가 단순해진다.
